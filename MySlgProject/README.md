# SLG游戏服务器架构

这是一个基于protoactor-go实现的SLG（策略类游戏）服务器架构，支持大地图分区管理和动态负载均衡。

## 架构特点

### 🎯 **核心特性**
- **动态地图分区**：支持运行时分区合并/分割
- **AOI管理系统**：高效的视野管理和状态同步
- **事件驱动架构**：基于actor模型的事件驱动设计
- **性能监控**：实时负载监控和自动调整

### 📊 **技术架构**

```
游戏世界
├── 空间索引 (SpatialIndex)
│   └── 四叉树分区
├── 分区管理器 (PartitionManager)
│   └── 动态分区 (Partition)
├── 实体管理器 (EntityManager)
│   ├── 玩家 (Player)
│   └── NPC (NPC)
├── AOI管理器 (AOIManager)
│   └── AOI订阅器 (AOISubscriber)
├── 状态同步器 (StateSyncManager)
├── 事件系统 (EventSystem)
└── 负载均衡器 (LoadBalancer)
    ├── 分区调整器 (PartitionAdjuster)
    └── 性能监控器 (MetricsCollector)
```

## 核心组件说明

### 1. **地图和分区系统**
- **SpatialIndex**: 使用四叉树进行空间索引，支持快速实体查询
- **Partition**: 地图分区，管理局部区域的格子状态和实体
- **GridState**: 格子状态管理，包含地形、资源、建筑等信息

### 2. **AOI管理系统**
- **AOIManager**: 为每个玩家管理可见区域，处理视野计算和状态同步
- **AOISubscriber**: AOI订阅机制，支持精确的状态变更推送

### 3. **动态分区调整**
- **LoadBalancer**: 监控分区负载，触发合并/分割决策
- **PartitionAdjuster**: 执行具体的分区调整操作，保证数据一致性
- **MetricsCollector**: 收集性能指标，支持趋势分析

### 4. **状态同步机制**
- **StateSyncManager**: 管理跨分区的状态同步，支持批量处理和增量更新
- **EventSystem**: 全局事件系统，支持发布订阅模式

### 5. **实体系统**
- **EntityManager**: 统一管理所有游戏实体
- **Player**: 玩家实体，支持移动、战斗、资源管理等
- **NPC**: 非玩家角色，支持AI行为和交互

## 性能特点

### 🚀 **性能优化**
- **空间分区**: 将1200×1200地图分成多个区域，减少单点压力
- **AOI优化**: 只同步玩家视野内的状态变更
- **事件批处理**: 批量处理相似的事件，减少消息传递开销
- **缓存机制**: 多级缓存减少重复计算

### 📈 **扩展性**
- **动态分区**: 根据负载自动调整分区大小
- **水平扩展**: 支持多服务器分布式部署
- **配置化**: 所有参数都可配置，支持不同规模的部署

## 配置说明

```yaml
world:
  width: 1200          # 地图宽度
  height: 1200         # 地图高度

aoi:
  view_range: 50       # 视野范围
  update_interval: 1s  # AOI更新间隔
  batch_size: 100      # 批量处理大小

partition:
  default_size: 100    # 默认分区大小
  min_size: 50         # 最小分区大小
  max_size: 200        # 最大分区大小
  monitor_interval: 30s # 监控间隔
  adjustment_cooldown: 5m # 调整冷却时间

performance:
  max_message_queue_size: 10000
  worker_pool_size: 10
  state_sync_batch_size: 50
  metrics_collect_interval: 10s
```

## 架构优势

### ✅ **解决的问题**
1. **大地图性能**: 通过分区避免单点瓶颈
2. **AOI效率**: 精确的状态同步，避免无效传输
3. **动态扩展**: 自动适应负载变化
4. **开发维护**: 模块化设计，易于扩展

### 🎯 **设计原则**
- **关注点分离**: 每个组件职责单一
- **事件驱动**: 松耦合的组件通信
- **性能优先**: 多层优化确保高性能
- **可观测性**: 完善的监控和日志

## 扩展方向

- **分布式支持**: 跨服务器的分区迁移
- **持久化存储**: 游戏状态的持久化保存
